# FactoryFlow / 交有数

简体中文 · [English](README.en.md)

小工厂的订单与交付工作台：收单、分批送货、看清待交，再与客户对账。

**Windows 本地开发者预览。** 适合了解业务流程、检查源码或试用合成样例的人；尚未通过生产或工厂实际使用验收。

![分批送货后的待交清单，保留各行单位和数量（合成演示）](docs/images/readme/zh-03-open-lines.png)

同一张合成订单：120 件交了 30 件，剩 90 件；35.5 千克交了 10.25 千克，剩 25.25 千克。不同单位分别计算。

## 从第一张订单开始

不必先整理完整客户库或物料库。客户可在录单时新建，订单也能不关联物料直接确认；有重复订单后，再把需要复用的行收录进物料池。

![从第一张订单开始：录单时新建客户，人工核对后生成订单，物料以后再整理（合成演示）](docs/images/readme/zh-first-order.gif)

合成示例，24 秒慢放节选（0.5 倍速）。识别等待及部分逐项核对已省略，不代表实际录单耗时。

1. **收单与核对**：上传图片/PDF，人工对照原件检查候选；也可直接手工录单。
2. **分批送货**：按订单行记录本次送货，查看已交和待交；作废保留历史并回退原数量。
3. **客户对账**：从送货明细建立草稿，记录发送依据和客户反馈，区分认可、待核对与暂缓数量。
4. **固定本期结算**：确认选定数量与金额，显式承接符合条件的后续余额，保留早期证据。
5. **整理输出**：导出内置或客户模板 Excel，整理订单原件、送货副本和对账文件。

![对照采购单人工补齐和校正后的四行候选，仍需确认生成订单（合成演示）](docs/images/readme/zh-02b-manually-reviewed.png)

上图是**人工核对后的候选**，不是自动识别成功的结果。本次合成样例的原始表格提取：中文得到 3 行结构化候选，英文得到 0 行；0 行不表示 OCR 没有读到文字。表格解析仍不可靠，两种语言都需要校正或补录。[演示证据说明](docs/README-SCREENSHOTS.md)保留了这个边界。

[中英文合成采购单](samples/purchase-orders/README.md)包含原件预览与参考明细。公司、联系人、标识和交易数据均为虚构，不含真实客户资料。

## 几个产品取舍

- **业务动作由人确认**：提取只提出候选，确认后才成为订单；客户认可与正式结算也是独立动作。
- **物料随订单积累**：物料池记录我方/客户料号，支持人工建档和核对后的 xlsx/UTF-8 CSV 导入。建档不产生库存，后续关联不改写已确认的原单字段。
- **数量和历史要准确**：保留原单位，数量与金额使用精确小数；确认版本不可变。每个业务事务同时提交审计、幂等结果和账本效果。

## 当前支持与限制

网页支持简体中文和 English；新内置对账 Excel、送货即时打印支持英文。切换语言保留客户名称、料号、备注和原件文字；客户模板保留原文，归档送货副本仍使用中文规则。

当前仅支持 **CNY**。客户认可和正式结算不代表收到付款；对账单与送货单不是税务发票。库存、付款处理、多币种和海外税务不在当前能力内。

预览发布将同时提供源码、Windows 离线安装包、第三方源码材料和校验值；下载入口为仓库的 Releases。构建与验证方法见[分发说明](docs/DISTRIBUTION.md)。原生 Excel、实体打印、真实资料兼容性与工厂使用仍需单独验收。已准备好的核心业务运行不依赖云端 AI 或在线账号；首次依赖安装需要联网。

## 本地开发

准备 Windows、Node.js 24（准确约束见 `package.json`）、uv、Python 3.14 和独立 PostgreSQL。按[本地运行说明](docs/LOCAL-OPERATIONS.md)完成依赖、配置、显式迁移与首个本地账号，再启动服务；启动本身不会自动迁移或重置数据。

前端与合同检查命令（需先准备开发环境）：

```powershell
npm run typecheck
npm run contracts:check
npm run build
```

这些检查不能替代真实业务或工厂验收。已验证范围与限制见[验证记录](docs/VERIFICATION.md)。
